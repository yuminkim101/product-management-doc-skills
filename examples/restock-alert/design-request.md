# 재입고 알림 신청 버튼 – 디자인 요청서

## 한눈에 보기
- **무엇을**: 품절된 상품 옆에 "재입고 알림 신청" 버튼을 새로 만든다
- **왜**: 기획서에 명시되지 않음 (확인할 것 1)
- **그려야 할 화면**: 1개 (① 품절 상품이 보이는 화면의 재입고 알림 신청 버튼). 버튼이 들어갈 화면 범위는 확인 후 확정 (확인할 것 2)
- **플랫폼**: 확인 필요 (확인할 것 3)
- **마감**: 협의 필요 (확인할 것 4)
- **아직 정해지지 않은 것**: 12건 → 맨 아래 "확인할 것" 참고

---

## 화면 ① 품절 상품 영역 – 재입고 알림 신청 버튼

**이 화면에서 사용자가 하는 일**
품절된 상품을 보고, 다시 들어오면 알림을 받기 위해 신청 버튼을 누른다.

**그려야 할 것**
- 품절 상품 옆 "재입고 알림 신청" 버튼 (가안)
- 버튼이 들어갈 위치: 상품 목록인지, 상품 상세인지, 장바구니·찜 목록까지 포함인지 확인 필요 (확인할 것 2)

**지켜야 할 규칙**
- 품절 상품에만 버튼을 노출한다
- 그 외 규칙은 기획서에 없음

**이런 경우도 그려 주세요**
- 신청하기 전 버튼 상태
- 신청한 뒤 버튼 상태: 버튼이 바뀌는지, 다시 눌러 취소할 수 있는지 확인 필요 (확인할 것 6)
- 신청 직후 사용자에게 보여 줄 안내: 토스트 메시지인지, 별도 창인지 확인 필요 (확인할 것 7)
- 로그인하지 않은 사용자가 버튼을 눌렀을 때 (확인할 것 5)
- 알림 수신 동의가 꺼져 있는 사용자가 신청할 때 (확인할 것 8)
- 신청이 실패했을 때 (확인할 것 9)
- 옵션 중 일부만 품절일 때 (예: 특정 사이즈만 품절) (확인할 것 10)

**문구**
- 버튼: "재입고 알림 신청" (가안, 기획서 표현 그대로 사용)
- 그 외 문구는 정해진 것 없음

## 화면 흐름
품절 상품 확인 → 버튼 누름 → (로그인 상태면) 신청 완료 안내 / (비로그인이면) 처리 방식 확인 필요

## 참고 자료
- 없음 (기존에 쓰는 버튼·토스트 컴포넌트가 있는지 확인할 것 11)

## 이번에 하지 않는 것
- 실제로 재입고됐을 때 받는 알림(푸시·문자 등) 내용과 디자인은 기획서에 없어 이번 요청에서 제외. 포함 여부는 확인할 것 12
- 신청 내역을 모아 보는 화면(예: 마이페이지)은 기획서에 없어 제외. 필요 여부는 확인할 것 12
