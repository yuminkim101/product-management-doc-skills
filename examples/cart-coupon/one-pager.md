# 원페이저 — 장바구니 쿠폰 적용

2026-10-28 · 작성자 · 버전 v0.1 · 상세 문서: 작성 전

## 1. 요약
- **상황:** 쿠폰은 주문서에서만 적용할 수 있어, 장바구니에서는 할인 금액을 미리 확인할 수 없다.
- **문제:** 할인 금액을 모른 채 장바구니에서 이탈하는 사용자가 있다.
- **근거:** 이탈 규모는 확인 전이다. (확인 필요)
- **해결 방안:** 장바구니에서 쿠폰을 골라 적용하고, 할인 금액과 결제 예정 금액을 바로 보여 준다.
- **사용자 가치:** 주문서까지 가지 않아도 최종 결제 금액을 알 수 있다.
- **비즈니스 효과:** 장바구니 → 주문서 전환율 개선 (목표치 확인 필요)

## 2. 가설
장바구니에서 쿠폰 적용 후 결제 예정 금액을 보여 주면, 장바구니에서 주문서로 넘어가는 사용자가 늘어날 것이다.

## 3. 핵심 지표
| 구분 | 지표 | 기준 |
|---|---|---|
| 핵심 | 장바구니 → 주문서 전환율 | 주문서 진입 수 ÷ 장바구니 진입 수. 목표치는 기준선 확인 후 확정 |
| 가드레일 | 확인 필요 | 예: 쿠폰 적용 오류 문의 수. 지표 선정 필요 |

## 4. 개발 범위
- **필수:** 쿠폰 적용 버튼, 쿠폰 목록 창(사용 가능·불가 구분), 쿠폰 1장 적용, 할인·결제 예정 금액 표시, 쿠폰 코드 직접 입력
- **출시 직후:** 확인 필요

## 5. 제외 범위
- 확인 필요 (메모에 명시된 제외 항목 없음)

## 6. 일정
디자인 마감 11/14. 개발·출시 일정은 개발 범위 확정 후 기입.

## 7. 확인 필요 사항
| 확인 필요 사항 | 담당 |
|---|---|
| 쿠폰을 몰라 장바구니에서 이탈하는 사용자가 실제로 많은가? | 데이터 분석가 |
| 장바구니에서 적용한 쿠폰이 주문서로 그대로 이어질 때, 주문서 화면도 바뀌어야 하나? | PM, 개발 |
| 가드레일 지표를 무엇으로 볼까? | PM |
