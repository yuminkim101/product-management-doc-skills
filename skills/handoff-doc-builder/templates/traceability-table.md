# 요구사항 매핑표와 변경 이력 양식

"추적성(traceability)"은 요구사항 하나가 어느 문서, 어느 화면·기능에 반영됐는지 끝까지 따라갈 수 있게 연결해 두는 것을 말합니다. 이 스킬은 요구사항 번호(REQ) 하나로 원본 기획서, 디자인 요청서의 화면, 개발 요청서의 기능을 연결합니다.

두 문서를 모두 쓰는 경우, 매핑표에 "디자인 화면"과 "개발 기능" 열을 둘 다 둡니다.

## 1. ID 규칙

| 구분 | 형식 | 예시 | 비고 |
|---|---|---|---|
| 요구사항 | REQ-두 자리 숫자 | REQ-07 | 원본 문서에 이미 다른 체계(예: FR-1)가 있으면 그 체계를 그대로 사용 |
| 화면 | SCR-두 자리 숫자 | SCR-03 | 관리 정보에서만 사용. 디자인 요청서 본문에서는 ①②로 표시 |
| 개발 기능 | 기능 + 숫자 | 기능 2 | 개발 요청서의 기능 순서 |
| 확인 필요 | Q-두 자리 숫자 | Q-02 | |

- 삭제된 ID는 재사용하지 않습니다. 재사용하면 변경 이력에서 다른 요구사항과 섞입니다.
- 하나의 요구사항이 둘로 쪼개지면 `REQ-07a`, `REQ-07b`처럼 원래 번호를 살립니다.

## 2. 매핑표 (신규 작성 시 함께 제시)

| REQ ID | 원본 위치 | 원본 문장(요약) | 연결 SCR | 연결 기능 | 상태 |
|---|---|---|---|---|---|
| REQ-01 | PRD 3.1 | | SCR-01, SCR-02 | 기능 1 | 반영 |

상태 값: 반영 / 미반영(사유 기재) / 확인 필요

## 3. 동기화 비교표 (모드 B)

| REQ ID | 판정 | 이전 내용 | 변경 내용 | 영향 SCR | 영향 기능 | 재작업 |
|---|---|---|---|---|---|---|
| REQ-03 | 변경 | | | SCR-02 | 기능 1 | 필요 / 불필요 / 확인 필요 |
| REQ-09 | 추가(신규 ID 부여) | - | | SCR-04 | 기능 3 | |
| REQ-05 | 삭제 | | - | SCR-03 | - | |

판정 값: 추가 / 변경 / 삭제 / 동일 (동일 항목은 표에서 생략하고 건수만 적어도 됨)

## 4. 변경 이력 (요청서 하단에 누적)

| 버전 | 날짜 | 변경 ID | 변경 내용 | 영향 화면 |
|---|---|---|---|---|
| v1.1 | YYYY-MM-DD | REQ-03, REQ-09 | 쿠폰 중복 적용 정책 변경, 자동 적용 추가 | SCR-02, SCR-04 |

버전 규칙
- 요구사항 추가·삭제·정책 변경: 소수점 첫째 자리 올림 (v1.0 → v1.1)
- 문구·오타 수정: 소수점 둘째 자리 (v1.1 → v1.1.1)
- 기능 범위 자체가 바뀌는 대규모 개편: 정수 자리 (v1.x → v2.0)

## 5. 디자이너 전달용 변경 요약 (모드 B)

```
[디자인 요청서 v1.1 변경 안내]
- 재작업 필요: SCR-02 (쿠폰 중복 적용 불가 → 2장까지 가능, REQ-03)
- 신규: SCR-04 쿠폰 자동 적용 안내 (REQ-09)
- 삭제: SCR-03의 쿠폰 코드 직접 입력 영역 (REQ-05)
- 확인할 것 2건: 요청서 맨 아래 "확인할 것" 참고
```
