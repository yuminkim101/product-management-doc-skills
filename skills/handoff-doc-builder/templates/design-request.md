# 디자인 요청서 양식

디자이너가 처음부터 끝까지 한 번 읽고 바로 작업에 들어갈 수 있게 쓰는 것이 목표입니다. 아래 원칙을 지킵니다.

- **본문은 문장으로 씁니다.** REQ·SCR 같은 관리용 번호는 본문에 쓰지 않고, 맨 아래 "관리 정보"에만 둡니다. 본문에서 화면은 ①②③으로 부릅니다.
- **표는 "확인할 것"과 "관리 정보"에만 씁니다.** 화면 설명은 목록으로 씁니다.
- **정해지지 않은 것은 한 곳에 모읍니다.** 본문에는 "(확인할 것 3)"처럼 번호만 붙이고, 질문 내용은 "확인할 것" 표에 씁니다.
- **해당 없는 항목은 지우지 말고 "없음"이라고 적습니다.** 빠뜨린 것인지 없는 것인지 구분할 수 있어야 하기 때문입니다.
- **문구가 기획서에 확정돼 있지 않으면 "(가안)"을 붙입니다.** 가안이 최종 문구로 굳는 일이 잦기 때문입니다.

---

```markdown
# [기능명] – 디자인 요청서

## 한눈에 보기
- **무엇을**: (기능을 한 문장으로)
- **왜**: (이 작업을 하는 이유 한 문장)
- **그려야 할 화면**: N개 (① 화면명 ② 화면명 …)
- **플랫폼**: 앱 / 웹 / 둘 다 (모르면 확인할 것으로)
- **마감**: (날짜, 모르면 확인할 것으로)
- **아직 정해지지 않은 것**: N건 → 맨 아래 "확인할 것" 참고

---

## 화면 ① [화면명]

**이 화면에서 사용자가 하는 일**
(한두 문장)

**그려야 할 것**
- (구성 요소와 위치)

**지켜야 할 규칙**
- (기획서에 있는 정책만. 없으면 "없음")

**이런 경우도 그려 주세요**
- (로딩 중, 데이터 없음, 오류, 조건 미달 등 화면이 달라지는 상황)

**문구**
- (확정 문구 / 가안 표시. 없으면 생략 가능)

---

## 화면 ② [화면명]
(같은 구조 반복)

---

## 화면 흐름
① → ② → (완료 시 어디로 / 실패 시 어디로)
※ 화면이 3개 이하이고 흐름이 단순하면 생략 가능

## 참고 자료
- 레퍼런스, 재사용할 기존 컴포넌트 (없으면 "없음")

## 이번에 하지 않는 것
- (범위 밖 항목, 없으면 "없음")

## 확인할 것
| 번호 | 질문 | 누구에게 |
|---|---|---|
| 1 | | PO / 개발 / 법무 |

---

<details>
<summary>관리 정보 (기획서와 연결용, 디자이너는 안 봐도 됨)</summary>

| 기획서 항목 | 내용 | 반영 화면 |
|---|---|---|
| REQ-01 | | ① |

| 버전 | 날짜 | 변경 내용 | 영향 화면 |
|---|---|---|---|
| v1.0 | YYYY-MM-DD | 최초 작성 (원본: 기획서 제목·버전) | - |

</details>
```

---

## 작성 메모
- 화면이 8개를 넘으면 "한눈에 보기" 아래에 화면 묶음(예: 진입 / 선택 / 완료)을 먼저 보여 줍니다.
- 동기화로 버전이 올라가면 "한눈에 보기" 맨 아래에 "**이번 변경**: (한 줄 요약)"을 추가하고, 바뀐 화면 제목 옆에 "(v1.1 변경)"을 붙입니다.
