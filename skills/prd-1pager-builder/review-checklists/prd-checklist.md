# PRD 점검표

항목별로 통과 / 보완 필요 / 해당 없음. 보완 필요는 고치거나 18장 확인 필요 사항으로 옮긴다.

## 구조
- [ ] 장이 양식 순서대로 모두 있고, 본문 참조("18장 확인 사항 2", "원칙 4")가 실제 위치와 맞다
- [ ] 문서 정보의 버전·수정일이 변경 이력 마지막 줄과 맞다

## 사실과 가정
- [ ] 확인되지 않은 주장에 (가정)이 있고, 핵심 가정은 18장에 확인 방법·담당이 있다
- [ ] 지어낸 수치·날짜·출처가 없다. 모르는 값은 "미정"
- [ ] 벤치마킹 사례에 출처 링크가 있다

## 논리 연결
- [ ] 문제(4장) → 원인(5장) → 가설(6장) → 해결 방안(9장)이 이어진다
- [ ] 현재 대안의 한계가 해결 방안으로 풀린다
- [ ] 해결하는 원인마다 REQ 번호가 있고, 목표(7장)마다 15장에 지표가 있다

## 요구사항
- [ ] REQ-01부터 두 자리 번호, 표 바로 위에 REQ 주석이 있다
- [ ] 완료 조건으로 통과·실패를 판단할 수 있다
- [ ] 필수 REQ마다 화면이 있거나 "화면 없음(서버 동작)"이 표시돼 있다

## 빈틈
- [ ] 13장에 대상 삭제, 중복 동작, 권한 없음, 외부 연동 실패, 회원 탈퇴가 검토돼 있다
- [ ] 15장에 가드레일 지표가 있고, 지표 계산에 필요한 기록이 14장에 있다
- [ ] 16장에 법·정책 제약과 다른 팀 의존성이 빠지지 않았다
- [ ] 17장 출시 후 검증에 유지·개선·중단 판단 기준이 있다
- [ ] 18장 확인 사항마다 담당과 기한(모르면 "미정")이 있다

## 원페이저와 일치 (원페이저가 있을 때)
- [ ] 요약·가설·핵심 지표·범위·제외 범위의 결론이 원페이저와 같다
- [ ] 원페이저의 확인 필요 사항과 피드백 결과가 18장에 모두 옮겨졌다
- [ ] 결론이 달라졌다면 이유가 18장 결정 사항에 있고, 원페이저 수정 여부를 사용자에게 물었다
