# 원페이저 양식

의사결정자가 3분 안에 읽고 방향에 답을 줄 수 있게 쓴다. PRD와 별도 문서로 만든다.

- 먼저 쓸 때: 메모에 있는 사실로만 쓴다. 모르는 칸은 "확인 필요"로 두고 7번에 질문으로 올린다. 상세 문서는 "작성 전".
- PRD를 요약할 때: PRD 문구를 줄여 옮기고 새 내용을 더하지 않는다.
- REQ 번호는 쓰지 않는다. 기능 이름이 더 빨리 읽힌다.

## PRD 장 대응표

원페이저 → PRD는 왼쪽을 오른쪽 장에 이어받는다. PRD → 원페이저는 반대로 줄여 옮긴다.

| 원페이저 | PRD |
|---|---|
| 1. 요약 (상황·문제·해결 방안·비즈니스 효과) | 1장 요약 |
| 1. 요약 (근거) | 4장 근거 표 첫 행 |
| 1. 요약 (핵심 흐름) | 8장 사용자 여정, 9장 채택한 방법 |
| 2. 가설 | 6장 가설 |
| 3. 핵심 지표 | 15장 핵심·가드레일 행 |
| 4. 개발 범위 (필수·출시 직후) | 10장 기능 목록 (REQ 번호와 완료 조건을 붙임) |
| 4. 개발 범위 (핵심 정책) | 10장 공통 원칙 |
| 5. 제외 범위 | 방법을 안 쓰기로 한 것은 9장, 이번에 뺀 기능은 12장 |
| 6. 일정 | 17장 출시와 검증 |
| 7. 확인 필요 사항 | 18장 확인 필요 사항 |
| 8. 피드백 요청 사항 | 답을 받았으면 18장 결정 사항, 아직이면 확인 필요 사항 |

나머지 PRD 장(2·3·5·7·11·13·14·16·19장)은 PRD를 쓸 때 새로 채운다.
